# Техническое задание: Виш-лист подарков ко дню рождения

## 1. Цель
Создать сайт (открывается в браузере, без установки приложения) со списком желаемых подарков для дня рождения дочери. Зарегистрированные гости (родственники, друзья) просматривают список, бронируют подарки, чтобы избежать дублирования, и переходят по ссылкам на конкретные товары на Ozon.

## 2. Роли пользователей

| Роль | Возможности |
|------|-------------|
| **Владелец** (родитель) | Создаёт/редактирует/удаляет позиции, видит статус всех бронирований и кто что забронировал; может вручную добавить гостей без Telegram |
| **Гость** | Просматривает список, бронирует подарки, видит и отменяет свои брони в личном кабинете |

## 3. Функциональные требования

### 3.1. Карточка подарка
Каждая позиция содержит (все поля заполняются вручную владельцем):
- Название
- Описание (необязательно)
- Фото (загрузка файла)
- Цена (ориентировочная)
- Ссылка на товар на **Ozon** (одна ссылка на позицию)
- Категория/тег (игрушки, книги, одежда, творчество…)
- Приоритет (★ очень хочу / ✦ было бы здорово)
- Статус: `свободно` / `забронировано`
- Флаг «можно дарить нескольким» (необязательно)

### 3.2. Управление списком (для владельца)
- Добавление позиции вручную
- Редактирование и удаление позиции
- Сортировка (по приоритету, цене, дате добавления)
- Дублирование позиции

### 3.3. Бронирование (для гостя)
- Кнопка «Забронировать» **на каждой карточке** — бронирование происходит **поштучно**, по одной позиции за раз.
- Форма бронирования: **комментарий** (обязательно). Имя гостя берётся из профиля, других полей нет.
- Один подарок может быть забронирован только одним гостем (если у позиции не включён флаг «можно дарить нескольким»).
- Один гость может забронировать несколько разных подарков — ограничения нет.
- Статус «забронировано» **виден владельцу** (видно, какая позиция и кем забронирована, с комментарием).
- Для остальных гостей позиция отображается как «уже выбрали» — без раскрытия имени бронирующего.
- Гость видит свои брони в личном кабинете и может отменить их сам.

### 3.4. Доступ

Авторизация подробно описана в [module1-spec.md](module1-spec.md). Кратко:

**Для гостей:**
- Авторизация по паре **Имя + Дата рождения** (без пароля). Регистрация и вход — единая форма; если такая пара уже есть в БД, гость заходит в существующий аккаунт.
- Telegram-привязка опциональна, выполняется через ЛК после входа (бот: `/start <код>`).

**Для гостей без Telegram:**
- Сценарий полностью поддерживается. Гость пользуется сайтом без Telegram, видит свои брони и статусы в ЛК.

**Для админа** (родителя, единственный аккаунт):
- Вход в админку по **логину и паролю**.
- Telegram-привязка для получения уведомлений — через `/start <код>` (тот же механизм, что у гостей).

### 3.5. Уведомления
- Владельцу — в Telegram при каждом бронировании (позиция + имя гостя + комментарий).
- Гостю с привязанным Telegram — в Telegram: подтверждение брони, отмена брони, при необходимости напоминание о дате праздника.
- Гостю без Telegram — уведомлений нет, статусы видны только в личном кабинете на сайте.

## 4. Нефункциональные требования
- Адаптивная вёрстка (мобильный приоритет — гости открывают с телефона)
- Время ответа страницы списка < 1 с
- Русский язык интерфейса
- Хранение данных в БД с резервным копированием
- Защита от спама бронирований (rate-limit по IP)

## 5. Технический стек
- **Frontend**: Next.js + Tailwind
- **Backend**: FastAPI (Python)
- **БД**: PostgreSQL на **Supabase**
- **Хранение фото**: Supabase Storage
- **Telegram-бот**: **aiogram** (для привязки аккаунтов через `/start <код>` и отправки уведомлений)
- **Хостинг**: фронт на Vercel, бэк на Railway / Fly.io / VPS
