# Модуль 4. Личные / развлекательные конкурсы

## 1. Цель
Четыре развлекательных конкурса, проводимых **админами в режиме ведущего** на банкете. Гости **не взаимодействуют с конкурсами через сайт** — все ответы либо на бумаге (с админ-вводом цифр), либо устно (с админ-фиксацией имени), либо вообще без ввода (Конкурс 4 — полностью бумажный, система только показывает название знака на проекторе). Результаты выводятся на проектор в реальном времени.

## 2. Архитектура

### 2.1. Роли
- **Ведущий** — админ в специальном режиме «Ведущий». Открывает на телефоне страницу `/host`. Любой из двух админов (мама/папа) может включить этот режим.
- **Проектор** — отдельная страница `/projector`, открыта на ноутбуке/ТВ в зале. Синхронизируется с телефоном ведущего через WebSocket.
- **Гости** — не взаимодействуют. (Раздел «Мои конкурсы» удалён из ЛК; см. §11.)

### 2.2. Режим ведущего на телефоне
- Доступ: только админ (после логина в админку → кнопка «Включить режим ведущего»).
- Что видит: список 4 конкурсов с их статусом (`не запущен` / `активен` / `закрыт`) и кнопки управления текущим.
- **Конфликт между двумя ведущими:** last-write-wins, без блокировок. Оба админа могут одновременно нажимать кнопки; результат — кто последний нажал, тот и побеждает.

### 2.3. Проектор
- URL `/projector` — без авторизации (читает только то, что транслирует бэк по WebSocket; не принимает действия).
- Открывается единожды на устройстве в зале и больше не закрывается всё мероприятие.

## 3. Конкурс 1. «На кого похожа»

### 3.1. Подготовка
- Админ в админке заводит:
  - **15 черт** (текстом: «глаза», «улыбка», «как зевает» и т.д.)
  - **Опорное фото** — одна композиция: Амалия + родители в детстве + родители сейчас
- Админ нажимает «Скачать бланк» → получает **PDF** со списком 15 черт, у каждой — 4 чекбокса:
  - ☐ Как мама
  - ☐ Как папа
  - ☐ Как другой родственник: __________
  - ☐ Уникально (только её)
- Админ печатает 30 копий и раздаёт гостям перед началом конкурса.

### 3.2. Проведение
- Гости заполняют бланки ручкой.
- Админ собирает бланки.
- В админке для каждой из 15 черт админ вводит:
  - Сколько голосов «как мама»
  - Сколько голосов «как папа»
  - По «другому родственнику» — список имён с количеством («Иван — 3», «бабушка Лида — 1»)
  - Сколько голосов «уникально»
- Можно редактировать введённые цифры до закрытия конкурса.

### 3.3. Вывод на проектор
- По каждой черте — круговая диаграмма распределения голосов в %.
- Общий итог конкурса в финале:
  - Если суммарно «маминых» больше → **«Мама фейс»**
  - Если суммарно «папиных» больше → **«Папа фейс»**
  - Если «уникальных» больше всего → **«Сама уникальность»**
  - Если «других родственников» больше всего → **«В кого-то из родни — <имя самого частого>»**

## 4. Конкурс 2. «Знаете ли вы»

### 4.1. Подготовка
- Админ создаёт **15 вопросов**. У каждого:
  - Текст вопроса
  - 4 варианта ответа
  - Индекс правильного варианта

### 4.2. Проведение
- Ведущий нажимает «Следующий вопрос» → проектор показывает текст + 4 варианта.
- Гости устно кричат ответ.
- Ведущий нажимает «Показать правильный ответ» → проектор подсвечивает правильный.
- Ведущий вводит **имя первого правильно ответившего**:
  - Выпадающий список зарегистрированных гостей + поле для незарегистрированного (текст).
- Можно редактировать имя до закрытия конкурса.
- После 15 вопросов проектор показывает таблицу: имя → сколько раз попадал в первые правильные.
- **Победитель** — у кого больше всего.

## 5. Конкурс 3. «50 обещаний»

### 5.1. Подготовка
- Админ создаёт **50 текстов обещаний** в админке.
- Перед конкурсом ведущий нажимает «Раздать обещания» → система случайно назначает каждому зарегистрированному гостю **одно** обещание. Лишние 20 обещаний остаются нерозданными в пуле.
- Гость **не видит** своё обещание заранее (даже в ЛК).

### 5.2. Проведение
- Ведущий выбирает гостя из списка → проектор показывает: «<имя гостя>, твоё обещание: <текст>».
- Гость встаёт и зачитывает.
- Ведущий помечает «прочитано» → переходит к следующему.
- Конкурс закрывается, когда все назначенные обещания прочитаны (или когда ведущий нажимает «Закрыть»).

### 5.3. Видимость до банкета
- Тексты обещаний и распределение видны **только админам**.
- Гость узнаёт своё обещание в момент, когда ведущий показывает его на проекторе.

## 6. Конкурс 4. «Знак зодиака»

### 6.1. Подготовка
- Списки **12 знаков × 10 черт** хранятся в системе (см. `zodiac-traits-catalog.md`, заполняется при инициализации БД).
- Админ нажимает «Скачать бланки» → получает 12 PDF (по одному на знак), каждый со списком 10 черт и местом для отметки.
- Админ печатает: для каждого знака столько копий, сколько у него зарегистрированных представителей (вычисляется автоматически на основе ДР гостей).

### 6.2. Проведение
- Ведущий нажимает «Следующий знак» → проектор показывает только **название знака** (например, «♌ Лев»).
- Все гости-Львы получают свои бумажные бланки. Каждый выбирает по 1 черте, отмечает галочкой, передаёт следующему и зачитывает свою.
- Ведущий после прочтения переходит к следующему знаку.
- **Знаки без гостей пропускаются автоматически** (проектор показывает только знаки, где есть представители).

### 6.3. Что хранит система
- Тексты черт по знакам.
- Список гостей в каждом знаке (вычисляется из ДР).
- Шаблон PDF-бланка.
- **Результаты выбора гостей в систему НЕ вводятся** — это полностью «бумажный» этап.

## 7. Управление через `/host`

Стартовый экран ведущего на телефоне:

```
[ Конкурс 1: На кого похожа     ] [статус] [Управление]
[ Конкурс 2: Знаете ли вы       ] [статус] [Управление]
[ Конкурс 3: 50 обещаний        ] [статус] [Управление]
[ Конкурс 4: Знак зодиака       ] [статус] [Управление]
```

Внутри каждого конкурса — пульт с кнопками:
- Запустить / Закрыть
- Следующий шаг / Назад
- Показать ответ (только Конкурс 2)
- Ввести данные (зависит от конкурса)
- Скачать PDF-бланки (Конкурс 1, 4)

## 8. Страница `/projector`

- Открывается на ноутбуке/ТВ один раз.
- Показывает текущее состояние, что транслирует ведущий: пустой экран / название конкурса / вопрос / результат / финальная таблица.
- Анимации переходов между состояниями (фейд / слайд).

## 10. Real-time синхронизация

- **Ведущий → бэк:** REST POST на `/api/host/action` (next, show_answer, set_winner, ...).
- **Бэк → проектор:** WebSocket-канал `/ws/projector`. Бэк пушит обновления состояния.
- **Бэк → ведущий:** при изменениях другим ведущим — WebSocket-канал `/ws/host` (чтобы оба админа видели актуальное состояние).
- Один активный `/projector`-сокет, до 2 одновременных `/host`-сокетов (мама и папа).

## 11. Последствия для других модулей

### Module 1 (`module1-spec.md`)
- **Раздел 2 (роли)** — админ становится «два аккаунта (мама и папа)» с равными правами.
- **Раздел 5 (авторизация админа)** — теперь два логина+пароля, оба создаются при инициализации.
- **Раздел 7 (ЛК)** — пункт «Мои конкурсы» **удаляется** (гости не взаимодействуют с конкурсами через сайт).
- **Раздел 8.1 (50 героев)** — становится 51, добавляется Бонифаций (#51, закреплён за папой-админом). Котёнок Гав (#49) — закреплён за мамой-админом.
- **Раздел 8.3 (логика выдачи)** — пул для гостей = 49 (исключаются #49 и #51).
- **Раздел 9 (БД)** — таблица `admin` поддерживает несколько строк (структура не меняется); `avatars` получает второй ряд `reserved_for_admin = true` для Бонифация.
- **Уведомления** — теперь отправляются **обоим** админам.
