# Проект «Amaliya»: обзор

Веб-приложение к дню рождения дочери. Гости получают единую точку входа, где они могут узнать всё о мероприятии, выбрать и забронировать подарок, а также поучаствовать в конкурсах (развлекательных и соревновательных) — результаты выводятся на проектор в зале.

Проект состоит из **5 модулей**. У каждого будет своё детальное ТЗ; этот файл — высокоуровневая карта проекта.

---

## Модуль 1. Регистрация и личный кабинет
Единая авторизация для всех остальных модулей.

**Детальное ТЗ:** [module1-spec.md](module1-spec.md)

**Сценарии:**
- Гости — вход по паре **Имя + Дата рождения** (без пароля). Регистрация и вход — единая форма; первая попытка с новой парой создаёт аккаунт, повторная пускает в существующий.
- Каждому гостю авто-присваивается уникальный аватар-сказочный герой из набора (49 для гостей, 1 закреплён за админом).
- Админ — вход по логину и паролю; может вручную создавать/редактировать/удалять гостей.
- Telegram-привязка (опционально для гостей, для уведомлений админу) — через бота `/start <код>`.

**Связь с другими модулями:**
- Авторизация — обязательна для модулей 3, 4, 5
- Список зарегистрированных гостей отображается в модуле 2

**Статус ТЗ:** ✅ готово (`module1-spec.md`).

## Модуль 2. Страница мероприятия
Информационная страница для всех зарегистрированных гостей + интерактив.

**Детальное ТЗ:** [module2-spec.md](module2-spec.md)

**Содержит:**
- Шапка с обратным отсчётом до Крестин
- Две карточки события: **Крестины** и **Банкет** (время, адрес, программа, ссылка на Яндекс.Карты)
- Дресс-код, пожелания семьи, контакты родителей (фото + телефон + Telegram)
- Список гостей (имя, аватар, знак зодиака, год животного), сортировка по алфавиту, поиск по имени
- Галерея фото/видео именинницы (сетка 4×5 + лайтбокс): лайки, комментарии, гостевые видео-поздравления (≤30 сек, с модерацией)
- **Мини-игра «Ангел Амалия»** — поймай падающее, 60 сек, 3 попытки в день, накопительный счёт
- Лидерборд + объявление победителя на банкете
- **RSVP** (в ЛК) — отдельные статусы на Крестины и Банкет, фича «пары» с двусторонним подтверждением через Telegram

**Доступ:** только для зарегистрированных пользователей.

**Статус ТЗ:** ✅ готово (`module2-spec.md`).

## Модуль 3. Виш-лист подарков
Список желаемых подарков с бронированием.

**Детальное ТЗ:** [wishlist-spec.md](wishlist-spec.md)

Кратко: гости видят карточки подарков (название, фото, цена, ссылка на Ozon), бронируют поштучно с обязательным комментарием. Бронь видна владельцу; для других гостей позиция отображается как «уже выбрали» без раскрытия имени. Уведомления — в Telegram.

**Статус ТЗ:** ✅ готово.

## Модуль 4. Конкурсы — развлекательные
Четыре конкурса, проводимых **админами в режиме ведущего** на банкете.

**Детальное ТЗ:** [module4-spec.md](module4-spec.md)

**Конкурсы (порядок проведения):**
1. **«На кого похожа»** — 15 черт × 4 варианта (мама/папа/родственник/уникально). Голосование на бумаге, админ вводит подсчёты, проектор показывает % и итог.
2. **«Знаете ли вы»** — 15 вопросов × 4 варианта с правильным ответом. Гости отвечают устно, ведущий вводит имя первого правильно ответившего.
3. **«50 обещаний»** — 50 текстов, случайно по одному назначаются 30 гостям. Гость зачитывает своё обещание, увидев его на проекторе.
4. **«Знак зодиака»** — 12 знаков × 10 черт, бумажные бланки. Проектор показывает только название знака.

**Архитектура:**
- Гости не взаимодействуют с конкурсами через сайт.
- Ведущий (любой из двух админов) управляет конкурсами с телефона `/host`.
- Проектор `/projector` синхронизируется через WebSocket.
- Шаблоны бумажных бланков (Конкурс 1, 4) — генерируются системой в PDF.

**Статус ТЗ:** ✅ готово (`module4-spec.md`).

## Модуль 5. Конкурсы. Часть 2 — игровая, командный квиз («100 к 1»)
Командная игра с мультимедиа в реальном времени.

**Механика (черновик):**
- Гости делятся на команды
- Вопросы в стиле «100 к 1» с открытием вариантов
- Музыкальное сопровождение и видео-нарезки во время игры
- Командный счёт выводится на проектор
- В финале выбирается команда-победитель

**Открытые вопросы (для детального ТЗ):**
- Сколько раундов / вопросов в игре?
- Кто управляет ходом игры — отдельная роль «ведущего» в админке?
- Источник вопросов — заранее загружены админом или собираются с гостей через модуль 4?
- Откуда берутся видео и музыка — загружаются админом, плеер встроен в страницу-проектор?
- Как формируются команды — вручную админом, по жребию, по самозаписи гостей?

**Статус ТЗ:** не начато.

## Технический стек (общий для всех модулей)
- **Frontend:** Next.js + Tailwind
- **Backend:** FastAPI (Python)
- **БД:** PostgreSQL на Supabase
- **Хранение медиа** (фото, видео): Supabase Storage
- **Telegram-бот:** aiogram
- **Real-time для проектора** (модули 4, 5): TBD — вероятно WebSocket / Server-Sent Events на FastAPI
- **Хостинг:** фронт — Vercel; бэк — Railway / Fly.io / VPS

## Принципы работы над проектом

- Согласованные изменения автоматически коммитятся и пушатся в `Milentochka/Amaliya` (ветка `main`).
